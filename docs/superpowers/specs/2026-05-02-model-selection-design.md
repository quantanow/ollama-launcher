# Model Selection with JSON Data — Design Spec
*Date: 2026-05-02 (updated 2026-05-10)*

## Overview

Replace the hardcoded `MODELS` array in `bin/ollama-launch` with a JSON-derived, metadata-rich model picker. The user selects a model from a list showing pulls, tags, and input type. If the selected model has multiple variants, a second picker prompts for the exact variant (size, context window, input type). Recent-launches quick-pick appears first when history exists.

## Goals

- Show all 100 models from `models.json` during selection
- Display metadata: name, pulls, tags, input type
- For models with variants, show a variant picker with size, context window, input type
- For models without variants, use the base name directly
- Maintain zero runtime dependencies (pure bash)
- Keep each script single-file and self-contained

## Non-Goals

- Dynamic fetching from ollama.com at runtime
- Persisting user preferences beyond recent launches
- Preview pane or side-by-side comparison
- Non-interactive flags for model pre-selection (the script is interactive; flags are for listing/help/print)

## Architecture

```
User
  → [if history exists] pick recent (agent+model combo or agent)
  → pick agent (skip if chosen from recent popup)
  → pick model (metadata-rich list from JSON-derived arrays)
    → [if model has variants] pick variant
  → save_history
  → exec ollama launch "$agent" --model "$final_model"
```

### Data Layer

The JSON data is converted to bash indexed arrays at build time by `scripts/generate-model-data.js`. The generated block is embedded in `bin/ollama-launch`, replacing content between `# MODEL DATA BEGIN` and `# MODEL DATA END` markers.

Because bash does not support arrays of objects, we use parallel indexed arrays with index alignment:

```bash
# MODEL DATA BEGIN — generated by scripts/generate-model-data.js
MODEL_NAMES=("qwen3.6" "nemotron3" "granite4.1" ...)
MODEL_PULLS=("1.1M" "571.9K" "57.9K" ...)
MODEL_TAGS=("vision tools thinking" "vision tools thinking audio" "tools" ...)
MODEL_HAS_VARIANTS=(1 1 1 ...)  # 1 = has variants, 0 = no variants

# Per-model variant arrays (index 0 for first model, etc.)
MODEL_VARIANTS_0=("qwen3.6:latest" "qwen3.6:27b" "qwen3.6:35b" ...)
MODEL_SIZES_0=("24GB" "17GB" "24GB" ...)
MODEL_CONTEXTS_0=("256K" "256K" "256K" ...)
MODEL_INPUTS_0=("Text, Image" "Text, Image" "Text, Image" ...)
# MODEL DATA END
```

### Selection Layer

Two selection functions are extended:

- **`pick_fzf_raw`** — reads items from stdin. Accepts extra fzf flags via `"$@"`. Prints selected line or empty string if cancelled.
- **`pick_menu_raw`** — reads items from a file. UI output goes to stderr; selection printed to stdout. Validates numeric input.

A new function **`pick_model()`** builds formatted display lines from `MODEL_NAMES`, `MODEL_PULLS`, `MODEL_TAGS`, and `MODEL_INPUTS_N[0]`, then delegates to `pick_fzf_raw` or `pick_menu_raw`.

A new function **`pick_variant(index)`** uses the same machinery but sources from `MODEL_VARIANTS_N`, `MODEL_SIZES_N`, `MODEL_CONTEXTS_N`, `MODEL_INPUTS_N`.

### Display Format

**Model list (primary picker):**
```
qwen3.6             | 1.1M pulls     | vision tools thinking | Text, Image
nemotron3           | 571.9K pulls   | vision tools thinking audio | Text, Image
granite4.1          | 57.9K pulls    | tools              | Text
```

For models with `:cloud` variants, `cloud` is appended to the tags column at display time (not stored in `MODEL_TAGS[]`), so searching "cloud" in fzf finds them.

**Variant list (sub-picker, when applicable):**
```
qwen3.6:latest  | 24GB  | 256K context | Text, Image
qwen3.6:27b     | 17GB  | 256K context | Text, Image
qwen3.6:35b     | 24GB  | 256K context | Text, Image
```

For models without variants, the display shows the base name and metadata; selection completes immediately.

## Data Flow

1. **Build time:**
   - `scripts/fetch-models.js` scrapes ollama.com for top 100 models + variant data, writes `models.json`
   - `scripts/generate-model-data.js` reads `models.json`
   - Generates bash array declarations
   - Inlines them into `bin/ollama-launch` by replacing content between `# MODEL DATA BEGIN` and `# MODEL DATA END` markers

2. **Runtime — Recent Quick-Pick (conditional):**
   - `load_history()` reads `~/.ollama-launch-history` into `HISTORY_ENTRIES[]`
   - `pick_recent()` shows recent `agent|model` combos + separator + all agents in one popup
   - Selecting a recent entry sets both `RECENT_AGENT` and `RECENT_MODEL`
   - Selecting an agent sets only `RECENT_AGENT`

3. **Runtime — Agent Picker (skipped if agent chosen from popup):**
   - `pick_fzf` or `pick_menu` with the `AGENTS` array

4. **Runtime — Model Picker:**
   - `pick_model()` iterates `MODEL_NAMES` and builds display strings
   - Calls `pick_fzf_raw` or `pick_menu_raw` with the formatted list
   - Sets global `PICK_MODEL_INDEX` and `PICK_RESULT`

5. **Runtime — Variant Picker (conditional):**
   - If `MODEL_HAS_VARIANTS[index]` is `1`:
     - If `MODEL_VARIANTS_N` has exactly 1 entry: auto-select it, skip picker
     - If `MODEL_VARIANTS_N` has 2+ entries: call `pick_variant(index)`
   - If `MODEL_HAS_VARIANTS[index]` is `0`: use `MODEL_NAMES[index]` directly

6. **Runtime — Execution:**
   - `save_history(agent, final_model)` writes to `~/.ollama-launch-history`
   - If `OLLAMA_LAUNCH_TEST=1`: print command and exit 0
   - If `OLLAMA_LAUNCH_PRINT=1`: pretty-print command and exit 0
   - `exec ollama launch "$agent" --model "$final_model"`

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Invalid numeric input in menu | Re-prompt (existing `pick_menu_raw` behavior) |
| Model has zero variants | Use base name, skip variant picker |
| Model has exactly 1 variant | Auto-select it, skip picker |
| `fzf` not installed | Fall back to `pick_menu_raw`; prompt to auto-install |
| Empty model arrays | Print error and exit 1 |
| Non-TTY stdout | Disable colors, use simple menu |
| Unknown CLI flag | Print error and exit 1 |

## Testing

A `bats` test suite under `tests/`:

- `test_flags.bats` — all CLI flags (exit codes, output content)
- `test_data_inlined.bats` — array lengths, variant sub-array consistency, specific metadata values
- `test_end_to_end.bats` — mocked fzf and menu paths, agent/model/variant selection, history isolation

End-to-end tests use a mock `fzf` and mock `ollama` in `tests/mock_bin/` (created/torn down by `setup_file`/`teardown_file`). `FZF_SELECT` env var controls which item the mock fzf selects (grep match; falls back to first line). `FZF_SELECT_N` enables independent multi-stage selection.

## Build Scripts

`scripts/fetch-models.js` (Node.js):
- Scrapes ollama.com for top 100 models + variant data
- Writes `models.json`

`scripts/generate-model-data.js` (Node.js):
- Reads `models.json`
- Generates bash arrays for all 100 models
- For models without variants, emits empty variant arrays and sets `MODEL_HAS_VARIANTS=0`
- Inlines directly into `bin/ollama-launch` between markers

Run manually when `models.json` is updated:
```bash
node scripts/fetch-models.js              # fetch fresh data
node scripts/generate-model-data.js       # regenerate embedded arrays
```

## Files Changed

- `bin/ollama-launch` — replace `MODELS` array, add `# MODEL DATA BEGIN/END` markers, add `pick_model()`, `pick_variant()`, `pick_recent()`, history functions, updated main flow
- `scripts/fetch-models.js` — new build script that scrapes ollama.com
- `scripts/generate-model-data.js` — new build script that inlines data into `bin/ollama-launch`
- `tests/*.bats` — new test files

## Compatibility

- Bash 3.2+ (no associative arrays; `local` declarations separate from assignments)
- `fzf` optional (falls back to numbered menu)
- Colors auto-disabled when not a TTY
- Empty array + `set -u` guard required in bash 3.2 for potentially-empty arrays
