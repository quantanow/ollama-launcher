# Model Selection with JSON Data — Design Spec

## Overview

Replace the hardcoded `MODELS` array in `ollama-launch` with a JSON-derived, metadata-rich model picker. The user selects a model from a list that shows pulls, tags, and input type. If the selected model has multiple variants, a second picker prompts for the exact variant (size, context window, input type).

## Goals

- Show all 80 models from `models.json` during selection
- Display metadata: name, pulls, tags, input type
- For models with variants, show a variant picker with size, context window, input type
- For models without variants, use the base name directly
- Maintain zero runtime dependencies (pure bash)
- Keep the script single-file and self-contained

## Non-Goals

- Dynamic fetching from ollama.com at runtime
- Persisting user preferences or recent selections
- Preview pane or side-by-side comparison
- Non-interactive flags (`--model`, `--variant`) — the script is strictly interactive

## Architecture

```
User
  → pick agent (existing)
  → pick model (new: metadata-rich list from JSON-derived arrays)
    → [if model has variants] pick variant (new)
  → exec ollama launch "$agent" --model "$final_model"
```

### Data Layer

The JSON data is converted to bash indexed arrays at build time by a small Node script. The generated block is embedded at the top of `ollama-launch`, replacing the current `MODELS` array.

Because bash does not support arrays of objects, we use parallel indexed arrays with index alignment. The generated block is inlined directly into `ollama-launch` between `# MODEL DATA BEGIN` and `# MODEL DATA END` markers, preserving the single-file philosophy:

```bash
# MODEL DATA BEGIN — generated by scripts/generate-model-data.js
MODEL_NAMES=("granite4.1" "mistral-medium-3.5" ...)
MODEL_PULLS=("16K" "4,261" ...)
MODEL_TAGS=("tools" "vision tools thinking" ...)
MODEL_HAS_VARIANTS=(1 1 0 ...)  # 1 = has variants, 0 = no variants

# Per-model variant arrays (index 0 for first model, etc.)
MODEL_VARIANTS_0=("granite4.1:3b" "granite4.1:8b" "granite4.1:30b")
MODEL_SIZES_0=("2.1GB" "5.3GB" "17GB")
MODEL_CONTEXTS_0=("128K" "128K" "128K")
MODEL_INPUTS_0=("Text" "Text" "Text")
# MODEL DATA END
```

### Selection Layer

Two selection functions are extended:

- **`pick_fzf`** — already exists. We pass formatted display lines as the item list. `fzf` shows the line as-is; the function extracts the model name (first field before the separator).
- **`pick_menu`** — already exists. We print a numbered list with aligned columns. The function validates numeric input and returns the model name.

A new function **`pick_variant(index)`** uses the same `pick_fzf`/`pick_menu` machinery but sources from `MODEL_VARIANTS_N`, `MODEL_SIZES_N`, `MODEL_CONTEXTS_N`, `MODEL_INPUTS_N`.

### Display Format

**Model list (primary picker):**
```
granite4.1          | 16K pulls    | tools              | Text
mistral-medium-3.5  | 4,261 pulls  | vision tools thinking | Text, Image
qwen3.6             | 736.2K pulls | vision tools thinking | Text, Image
deepseek-v4-flash   | 38.2K pulls  | tools thinking cloud | (no variants)
```

**Variant list (sub-picker, when applicable):**
```
granite4.1:3b  | 2.1GB  | 128K context | Text
granite4.1:8b  | 5.3GB  | 128K context | Text
granite4.1:30b | 17GB   | 128K context | Text
```

For models without variants, the display shows the base name and metadata; selection completes immediately.

## Data Flow

1. **Build time:**
   - `scripts/generate-model-data.js` reads `models.json`
   - Generates bash array declarations
   - Inlines them into `ollama-launch` by replacing content between `# MODEL DATA BEGIN` and `# MODEL DATA END` markers

2. **Runtime — Model Picker:**
   - `pick_model()` iterates `MODEL_NAMES` and builds display strings
   - Calls `pick_fzf` or `pick_menu` with the formatted list
   - Returns the selected model index

3. **Runtime — Variant Picker (conditional):**
   - If `MODEL_HAS_VARIANTS[index]` is `1` and `MODEL_VARIANTS_N` has >1 entries:
     - Call `pick_variant(index)`
     - Return the selected variant name
   - If `MODEL_HAS_VARIANTS[index]` is `0`:
     - Return `MODEL_NAMES[index]` directly
   - If exactly 1 variant exists:
     - Skip picker, return the single variant name

4. **Runtime — Execution:**
   - `exec ollama launch "$agent" --model "$final_model_name"`

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Invalid numeric input in menu | Re-prompt (existing `pick_menu` behavior) |
| Model has zero variants | Use base name, skip variant picker |
| Model has exactly 1 variant | Auto-select it, skip picker |
| `fzf` not installed | Fall back to `pick_menu` |
| Empty model arrays | Print error and exit 1 |
| Non-TTY stdout | Disable colors, use simple menu |

## Testing

A `bats` test suite under `tests/`:

- `test_model_picker.sh` — mock `fzf`, verify `pick_model()` returns correct name
- `test_variant_picker.sh` — verify multi-variant triggers sub-picker, zero/one variant skips
- `test_display_format.sh` — verify column alignment and separator format
- `test_end_to_end.sh` — set `OLLAMA_LAUNCH_TEST=1` to print command instead of `exec`, verify full command string

## Build Script

`scripts/generate-model-data.js` (Node.js):

- Reads `models.json`
- Generates bash arrays for all 80 models
- For models without variants, emits empty variant arrays and sets `MODEL_HAS_VARIANTS=0`
- Writes to `src/model-data.sh`

Run manually when `models.json` is updated:
```bash
node scripts/generate-model-data.js
```

## Files Changed

- `ollama-launch` — replace `MODELS` array, add `# MODEL DATA BEGIN/END` markers, add variant picker, update `pick_model()`
- `scripts/generate-model-data.js` — new build script that inlines data into `ollama-launch`
- `tests/*.sh` — new test files

## Compatibility

- Bash 3.2+ (no associative arrays)
- `fzf` optional (falls back to numbered menu)
- Colors auto-disabled when not a TTY
